Deploy pi/ to the Pi

      
Runs bash pi/deploy.sh: copies pi/ over and installs what changed. The password goes to sudo on the Pi and is never saved or logged; the field clears after each run. A real deploy restarts the listener if its files or config.env changed (do it when the gym is closed).

Ship

          

          
          

            
            
            
          

          
Ship commits the ticked files (none ticked: it pushes what's committed) and pushes main, which deploys to real users, after one confirm. bash build.sh --check (the syntax check and the three-places rule) runs first, and Cloudflare runs it again: a failed build keeps the last good version live. CACHE is stamped by the build. Afterwards the live sw.js is polled until it shows the new stamp.

        2.

        3. 
        
      3. Over the hotspot: sudo systemctl stop pb-netwatch first, or it tears the hotspot down.
        4. 
        
      4. No SSH at all: take the SD card out and read netlog.txt and netwatch.txt from its boot partition.
