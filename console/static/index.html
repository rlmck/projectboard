      Deploy The Pi updates itself from main; by hand, and what differs from the repo.
      

    

      
Deploy pi/ to the Pi

      
This happens on its own: every 10 minutes the laptop puts main's Pi files on the Pi (console/autodeploy.py, a scheduled task): in opening hours only after 15 minutes with nobody using the board, outside them straight away. These buttons are for doing it by hand.

      
Runs bash pi/deploy.sh: copies pi/ over and installs what changed, with no password (the Pi's /etc/sudoers.d/pb-deploy rule). A real deploy restarts the listener if its files or config.env changed (do it when the gym is closed). On a freshly flashed card without that rule, run bash pi/deploy.sh in Git Bash once instead: it asks for the password and puts the rule back.

      1. Wait 4 minutes: pb-netwatch and pb-health retry the Wi-Fi, restart NetworkManager, and reboot if needed.
        2. 
        
      2. Still nothing: on site, look for the Wi-Fi network projectboard-rescue (the Pi opens it after about 4 minutes offline, for 15 minutes). Join it, then ssh pi@10.42.0.1.
        3. 
        
      3. Over the hotspot: sudo systemctl stop pb-netwatch first, or it tears the hotspot down.
        4. 
        
      4. No SSH at all: take the SD card out and read netlog.txt and netwatch.txt from its boot partition.
